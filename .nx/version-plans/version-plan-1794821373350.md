MI-331, MI-340: Update dependencies across all packages, throw `BatchOperationError` on S3 batch delete failures in `aws-wrappers`, and add per-stage config and a `remove-service` fix to `nx-cdk`.

**aws-wrappers** (MI-331): **Behaviour change** — `S3Service.deleteObjects` and `S3Service.emptyBucket` now throw a `BatchOperationError` when S3 reports per-key delete errors.

Previously `deleteObjects` resolved with the raw per-chunk output even when keys came back under `Errors`, and `emptyBucket` returned every key it had _issued_ a delete for, so a handler could assume objects were gone when they were not. `deleteObjects` still attempts every chunk before throwing; the error carries the per-chunk `results` and a normalised `failed` list of `{ id, code, message }`, where `id` is the object key. `emptyBucket` now returns only the keys that were actually deleted, continues through every page when one has failures, and throws a single aggregated error at the end whose `results` hold the deleted keys per page (`{ deletedKeys }`). A call where no key fails returns exactly what it did before, and request-level SDK exceptions still propagate unchanged.

Callers of these two methods should audit their call sites: code that relied on a resolved promise meaning "everything was deleted" will now see a thrown error, and should catch `BatchOperationError` to retry or report the failed keys.

**nx-cdk** (MI-340): The preset now generates `libs/infra/src/config.ts` for non-secret, per-stage configuration, replacing SSM Parameter Store in the generated templates.

Values are plain strings keyed by CDK stage name, and `SharedInfraStack` reads them with `getStageConfig`, which fails synth if a stage has no config or a value is still `TODO`. Because the values are written straight into each service stack's template, changing one is a normal deploy. Values read from SSM in `SharedInfraStack` reached service stacks as CloudFormation exports, which can't change while another stack imports them ("Cannot update export ... as it is in use by ..."). Secrets stay in Secrets Manager.

With `--example`, the example `SharedInfraStack` now exposes `exampleBaseUrl: string` from `EXAMPLE_CONFIGURATIONS` instead of `paramExample: IStringParameter`. The example's `prd` value is left as `TODO`, so an example workspace won't synth `prd` until it's filled in. The infra and service README templates now document stage config instead of SSM.

Existing workspaces are unaffected. To adopt the pattern in one, add `libs/infra/src/config.ts` and read it in `SharedInfraStack` as described in the generated `libs/infra/README.md`.

**nx-cdk** (MI-331): Fix `remove-service` refusing to remove any service without `--forceRemove`. The dependency check counted the main `application` as a dependent, but the application always references a service the `service` generator created, and the generator removes those references itself. The check now ignores the application and still blocks on any other dependent.

**All packages** (MI-331): Update dependencies.

`appbuilder-util-lib` moves `@adobe/aio-lib-db` from `0.1.0-beta` to `1.1.0`. `nx-openapi` moves `@redocly/openapi-core` and `ts-morph` to their next major versions; Redocly 2 is ESM-only, so it is now loaded with a dynamic `import()` inside `validateSchema`. Consumers with a `redocly.yaml` should check it against Redocly's v2 configuration changes. `nx-cdk` raises the dependency versions written into generated workspaces, including `@aligent/cdk-aspects` (`^0.8.1`), `@aligent/cdk-nodejs-function-from-entry` (`^0.3.0`) and `@aligent/vite-plugin-handler` (`^0.5.3`). `nx-appbuilder` raises `type-fest` in generated apps to `^5.10.0`.
