MI-331: Add `EventBridgeService`, `LambdaService` and a `required` option on `SSMService.getParameters` to `aws-wrappers`, and update `fast-xml-parser` in `microservice-util-lib`.

**aws-wrappers** (MI-331): Add `EventBridgeService` and `LambdaService`, plus a new `LambdaFunctionError`.

`EventBridgeService.putEvents` takes the SDK input unchanged, sends entries in chunks of ten, and after every chunk has been sent throws a `BatchOperationError` if EventBridge rejected any entry. Each failed entry's `id` is its index in the `Entries` list you passed in, as a string. The error carries the per-chunk `results` and the failed entries' `id`, `code` and `message` — never the event detail. Request-level SDK failures propagate unwrapped and nothing is retried.

`LambdaService.invoke` takes the SDK input unchanged and returns the SDK output unchanged, except that it throws `LambdaFunctionError` when the response carries a `FunctionError`. The error carries the function name, the function error value, and the error type and message parsed from the payload when it has the usual JSON shape; it never carries the raw response or stack trace. Async and dry-run invocations are unaffected.

Both wrappers log one INFO line per call with payload-carrying fields omitted (event detail and entries; invocation payload and client context), are X-Ray instrumented by default, and accept an injected client and logger. `LambdaFunctionError` has a fixed `name`, so match on `error.name` rather than `instanceof` when both the CJS and ESM builds may be loaded.

**aws-wrappers** (MI-331): `SSMService.getParameters` accepts `{ required: true }` to throw when any requested parameter does not exist, instead of silently returning `undefined` for a typo'd path.

Every chunk is still sent, then a single `BatchOperationError` is thrown naming every missing parameter: `failed[].id` is the parameter path, `failed[].code` is `ParameterNotFound` and `failed[].message` names the alias. Without the option, behaviour is unchanged. The TSDoc and README now document that `getParameter` throws on a missing parameter while `getParameters` returns `undefined` unless `required` is set.

**aws-wrappers** (MI-331): Share one `batchFailure` test helper across the SQS, SNS and EventBridge specs instead of redefining it in each. The helper lives in `src/util/batch-operation-error.test-helpers.ts`, which is excluded from the library build, so nothing new ships. There is no public API change.

**microservice-util-lib** (MI-331): Update `fast-xml-parser` to `5.12.1`, which fixes quadratic rescanning of malformed attributes in its XML validator (AIKIDO-2026-725485). `microservice-util-lib` doesn't enable validation, so it wasn't exposed, but consumers' security checks flag the pinned `5.12.0`.
