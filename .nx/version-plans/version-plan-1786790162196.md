feat(microservice-util-lib): add shouldRetry, calculateDelay, and deadline options to retryWrapper (MI-335)

- `shouldRetry` and `calculateDelay` now also accept async (Promise-returning) implementations.
- `onRetry` gains a `delayMs` parameter: the delay actually just waited, since `config.delay` already reflects the delay computed for the next retry.
- Adds an opt-in `exponentialJitter(baseDelay, maxDelay)` helper for use as `calculateDelay`, replacing the hand-rolled formula callers previously had to write themselves.
- Once `retries` are exhausted, the failing error is now rethrown immediately without a final wasted sleep or consulting `shouldRetry`/`calculateDelay`/`onRetry` for an attempt that was never going to happen — previously these ran once more, one recursion after they could have mattered. Callers using these hooks purely for side effects (e.g. logging) will now see one fewer invocation per exhausted `retryWrapper()` call.
- `deadline` now accounts for the delay before the *next* retry, not just elapsed time so far — previously a long delay could push the next attempt's start time past the deadline before the overrun was detected on the following attempt.
