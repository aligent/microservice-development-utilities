Modernise the App Builder app generator for @adobe/aio-commerce-lib-app 1.9.

Admin UI moves from commerce/backend-ui/1 to commerce/backend-ui/2, declared through the new adminUi key in app.commerce.config.ts. The hand-written registration action and UIX context components are replaced by createExtensionApp() from @adobe/aio-commerce-lib-admin-ui, on Spectrum S2. The sidebarCategory option is renamed to parentMenu and widened to the full set of Commerce admin menus.

Generated apps are now ESM, ship an app-root webpack-config.cjs that disables webpack's TypeScript experiment, gitignore the SDK's .generated directories, and resolve web action URLs through a generated registry (aio app get-url) instead of the per-extension config.json. The unreachable per-extension webpack configs are removed.

Commerce apps also declare the SDK's postinstall hook (guarded on .env), which only `aio-commerce-lib-app init` would otherwise write, and the root tsconfig now covers app.commerce.config.ts, vitest.config.ts and src/lib — so a bad adminUi or businessConfig entry fails check-types instead of surfacing at build time.

Also fixes three pre-existing faults that made a freshly generated app fail its own checks: the aio-lib-core-logging type shim was an ambient module declaration rather than an augmentation, prettier's tabWidth/printWidth disagreed with .editorconfig, and the app pinned an ESLint major that @aligent/ts-code-standards does not support.
